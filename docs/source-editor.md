# 信源管理与列表解析

后台侧栏「信源管理」（`/admin/sources`）支持 RSS、JSON GET 接口、HTML 栏目的新增、编辑、删除、开关和解析预览。修改保存在数据库，API 与 worker 读取同一配置；无需改 YAML 或重新构建容器。

## 操作

1. 点击「新增信源」，填写名称、类型、采集地址、检查间隔和内容类型。
2. RSS / Atom 自动读取标准字段。JSON 和 HTML 需要填写文章列表、标题、原文链接及发布时间的路径；表单可填入示例规则。
3. 点击「测试解析」查看前 5 条标题、链接、真实日期和摘要。解析失败会显示原因；单篇正文失败不妨碍查看其他成功条目。预览不保存文章、配置或断点，也不调用评分。
4. 点击「保存信源」。新建默认不启用，可勾选「保存后启用采集」，也可保存后在列表切换开关。
5. 删除信源只移除采集配置，保留已收录文章和历史进度。内置信源删除后也不会因容器重建恢复；需要时可重新新增。

Crossref 期刊补漏源在此页可以开关；名称、ISSN 及期刊增删由「关注面」统一管理。原有部委专用适配器可以编辑地址、名称、过滤等配置；候选网站可选择 JSON 或 HTML 类型并配置解析规则后接入。

## JSONPath 示例

采集地址返回：

```json
{
  "data": {
    "items": [
      {
        "id": "123",
        "title": "农业机器人田间试验取得新进展",
        "published_at": "2026-11-04 09:00:00",
        "summary": "该试验在多个农业示范基地验证了农业机器人在不同作物与地形条件下的作业能力，并公布了定位精度、节水效果及当前局限。"
      }
    ],
    "next_url": "https://example.org/api/news?page=2"
  }
}
```

| 字段 | JSONPath / 配置 |
| --- | --- |
| 文章列表 | `$.data.items`（也支持 `$.data.items[*]`） |
| 标题 | `$.title` |
| 原文链接 / ID | `$.id` |
| 链接模板 | `https://example.org/news/{value}` |
| 发布时间 | `$.published_at` |
| 摘要 | `$.summary` |
| 无时区日期 | `Asia/Shanghai` |
| 下一页 URL | `$.data.next_url`，选择「从响应读取下一页链接」 |

列表路径基于整个响应，其余字段路径基于每个条目。字段匹配多个值时使用第一个；列表必须为对象数组。链接模板中的 `{value}` 替换为编码后的字段值；如果接口已经返回完整或相对链接，直接选择链接字段，模板留空。原文链接中的业务查询参数（例如 `?id=123`）会保留，已知跟踪参数会被清理。

也可选择页码参数分页：填写参数名（如 `page`）、起始页码和每页条数。每页条数只用于判断末页，不会自动发送 `pageSize`；这类参数请直接写进采集地址。每页条数为 0 时，采集至空页。下一页链接和页码参数二选一。

JSONPath 使用 `jsonpath-ng`，支持字段、数组、通配符和扩展筛选语法，不执行 Python 脚本。

## HTML XPath 示例

对以下服务器返回的 HTML：

```html
<ul class="news-list">
  <li>
    <a href="/news/123">农业技术试验进展</a>
    <time datetime="2026-11-04T09:00:00+08:00">11月4日</time>
    <p>……文章摘要……</p>
  </li>
</ul>
<a rel="next" href="?page=2">下一页</a>
```

| 字段 | XPath |
| --- | --- |
| 文章列表 | `//ul[@class='news-list']/li` |
| 标题 | `./a`（读取元素文本，包括子元素文本） |
| 原文链接 | `./a/@href` |
| 发布时间 | `./time/@datetime` |
| 摘要 | `./p/text()` |
| 下一页 URL | `//a[@rel='next']/@href` |

条目 XPath 从整个页面选取元素，其余字段相对条目取值；下一页路径仍从整个页面取值。页面通常使用 UTF-8；非 UTF-8 页面回退到页面声明的编码。需要先由 JavaScript 渲染才出现的列表不在此通用适配器的范围内。

## 日期、原文与限制

- ISO 日期、秒与毫秒时间戳自动识别。其他格式可填写 `strptime` 格式，例如 `%Y年%m月%d日`；未标时区的日期使用配置时区。
- 标题、链接和真实发布日期必填，不以抓取时间替代。摘要可不映射：如果没有足够的摘要或列表正文，会尝试直接读取原文正文，正文至少 200 字符才接收入库；已有摘要至少 40 字符。
- 「论文」类型需要配置 DOI 路径；生成论文元数据并按 DOI 与其他来源去重，JSON / HTML 论文在后台可按来源筛选。
- 允许域名自动包含采集地址的主机名，原文在其他域名或跳转到其他主机名时需另行填写。文章路径正则可进一步限定采集范围。系统校验公开互联网地址以及每次跳转，不读取本机或内网地址。
- 当前通用接口仅支持公开 GET 请求、RSS / Atom、JSON 和静态 HTML；不配置登录 Cookie、任意脚本或 POST 请求。专有接口可继续通过专用适配器接入。
- 响应解压后最多 8 MB、每页最多 500 条、每轮最多 5 页；分页列表应为最新在前。正常采集继续遵守回看窗口、每源新建上限、去重、评分和失败断点规则。

## 持久化与修改生效

出厂清单仍在 `app/sources.yaml`。后台新增、覆盖和删除标记保存在 `pipeline_state` 的 `source_definition:<id>`，开关仍使用 `source_enabled:<id>`。不需要新增表；出厂默认不会覆盖后台编辑。旧配置与仅有开关的数据继续兼容。

采集中编辑或删除来源后，旧任务在下一页前停止；已经开始的页面会处理完成。编辑配置后会识别配置版本变化，以新回看窗口重新采集，避免使用旧 URL / 解析器的分页断点；历史条目通过现有规则去重。只切换启用、停用时仍使用原断点。

管理员接口（均需管理令牌）：

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/admin/sources` | 列表、完整定义、开关与状态 |
| `POST /api/v1/admin/sources` | 新建定义，返回稳定 ID |
| `PUT /api/v1/admin/sources/{id}` | 保存完整定义 |
| `PATCH /api/v1/admin/sources/{id}` | 仅修改启用开关，兼容原接口 |
| `DELETE /api/v1/admin/sources/{id}` | 删除定义，保留文章 |
| `POST /api/v1/admin/sources/preview` | 用未保存定义进行真实只读预览 |

公开读取 API 不变。重复的同类型采集地址、无效路径、私有地址及不支持的定义返回 422；未知 ID 返回 404。
