# 加载性能优化 · 2026-10-23

访问诊断发现首页一次获取 100 篇完整文章，正文又被内联进 Nuxt SSR 数据。
线上首页 HTML 为 1,092,865 字节，文章列表为 757,254 字节，正文占列表响应约 64%。
CDN 命中和 gzip 已确认可用；健康接口仍存在网络或回源延迟，需要源站对照测速才能进一步归因。

本次改动：

- 网页请求 `compact=true`，文章列表、主题检索、相关文章与日报内文章省略正文、评分明细和分类审计信息；数据库同时跳过这些列和分类关系加载。
- 公开 API 默认完整格式保持兼容，文章详情、管理员接口及 Agent 接入保留原行为。
- 首页和标签页每页 20 条，提供前后翻页，保留筛选参数及分页 canonical 地址。
- 卡片的编辑弹窗按需加载，并在打开时读取完整详情，保存时保留正文和主题锁定状态。
- 日报文章使用批量查询，按原 ID 顺序输出并跳过缺失文章；API 支持 gzip。

使用诊断时保存的线上 100 篇文章，在隔离的本机 PostgreSQL + pgvector 与 Nuxt 生产构建中验证：

| 数据 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 首页 HTML，未压缩 | 1,092,865 B | 116,046 B |
| 100 条文章列表，未压缩 | 757,254 B | 191,026 B |
| 首页列表，未压缩 | 757,254 B（100 条） | 41,769 B（20 条） |

首页 HTML 减少约 89%，首页列表减少约 94%。本地 HTML 的 gzip 体积约 30 KB，
实际线上传输压缩与耗时需要部署后复测；本地结果不代表 CDN 或用户网络已改善。

验证：后端全量 265 项通过、2 项跳过（未提供真实 GLM 凭据），包含 SQLite 与真实 PostgreSQL。
新增检查覆盖轻量响应与完整卡片字段一致、SQL 不读取大字段、分页、详情完整性、日报顺序和 gzip。
前端 12 项测试及 Nuxt 生产构建通过。本机 Google Chrome 验证首页/分类/标签翻页及刷新、
详情、日报、卡片编辑保存；正文、主题及锁定状态保留，无页面脚本错误。未使用模拟器。

改动尚未部署线上，无数据库迁移要求。发布时更新后端和前端镜像即可；
旧前端兼容新后端，新前端配旧后端仍可显示，但无法获得完整的数据精简收益。
