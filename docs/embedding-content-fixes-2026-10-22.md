## 修复

- 重复推送：所有去重分支共用的信源合并函数现在会补入空正文，已有正文保持不被重复推送覆盖。
- 保存事务：后台入库补抓、管理员手动抓取和批量抓取均先保存正文，再做可选评分；
  评分异常回滚派生修改，不会撤回正文。批量后续任务取消也不会丢失之前已保存的正文。
- 自动回补：将最后处理的文章 ID 写入 `pipeline_state`，下一批继续向后处理并循环回绕，
  避免固定的前 20 条失败记录阻塞后续文章。已精选文章也可以补齐正文。
- 主题页：空结果显示提示并设置 `noindex`；接口失败提供重试。
  中文错误提示改用 `message`，不再放入 HTTP `statusMessage`。
- 中文路径：实际 Chrome 验收发现 Nuxt 的外置 payload URL 被重复编码，触发 HTML 当作
  JSON 解析和水合不一致。关闭独立 payload 提取，SSR 数据内联到页面；保留现有 SWR 页面缓存。
- 向量成功标记：卡片、详情、后台标题旁显示小型层叠勾选图标，仅当前模型指纹的 `ready`
  任务显示。内容变更进入待索引，或切换模型后，图标立即消失。
- Logo：扁平几何 A 与浅绿田垄切面；统一公开页、后台、登录页、日报分享卡、favicon、
  Apple 图标及社交分享图。SVG 源文件随仓库保存。

## Embeddings 429

查询和回填共用单进程请求节奏及冷却状态：

- `EMBEDDING_MIN_INTERVAL=1`：请求启动至少间隔 1 秒，串行发送。
- `EMBEDDING_RATE_LIMIT_COOLDOWN=60`：429 初始冷却 60 秒；连续失败指数退避至 1 小时。
- 更长的 `Retry-After` 继续遵循，支持秒数和 HTTP 日期，最长 24 小时。
- 冷却期间暂停后续回填，新查询返回关键词结果，已有查询向量缓存仍可使用。
- 安全地记录四位数字业务码，管理后台显示 `provider_http_429_1302` 等原因。
  智谱 `1113` 识别为 `provider_insufficient_balance`，暂停 1 小时。

429 也可能表示欠费；原始单行 HTTP 日志不足以判断具体原因。
业务码含义见[智谱官方错误码](https://docs.bigmodel.cn/cn/api/api-code)。
限速状态按进程共享，多进程、多个实例或独立 CLI 的总请求量仍需按账户额度配置。

SQLite 的空向量存储同时改为 SQL NULL，防止 JSON null 被误计为已生成向量。
索引出现错误后不会仅凭旧计数将失败任务提升为成功。
