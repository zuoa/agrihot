# 热点专题挖掘重构调研（2026-11-11）

## 结论

当前失败的主要原因在成稿之前：系统先让模型从最多 300 篇文章中同时提出议题、选择材料和声明证据组，然后用篇数、日期、DOI、引文字符串等程序规则检查。程序没有验证每篇核心材料是否回答**同一个具体问题**，也没有验证证据组是否真是独立研究或独立消息来源。后续独立审稿虽会检查这些关系，但已经收到混杂的材料，且一次修稿不能改变来源、角色和议题范围。

建议把自动专题改成“候选事件/问题 → 逐篇筛选 → 同源合并 → 可回答性判定 → 有界检索 → 逐条主张 → 综合 → 发布前复核”的流水线。任一环节证据不足就留在候选池。**放弃产出也是正确结果**，不能为了满足每天的专题数量、三篇核心或三条发现而吸收邻近题材。

此文是重构设计和评估方案，尚未用 #15–#25 的原始来源快照验证新方法。下表仅将用户提供的审核意见转成预期行为，不能当作完整人工标注。

## 现状与失败模式

| 环节 | 当前实现 | 审核意见显示的缺口 |
| --- | --- | --- |
| 发现 | `load_candidates` 按分类轮流取最多 300 篇；`DISCOVER` 一次返回标题、范围、3–6 篇文章、角色、证据组和外部查询 | 大量宽泛相似材料进同一上下文；模型为凑三篇而扩大事件或研究问题 |
| 材料门槛 | `eligibility_report` 检查 3 篇核心、2 个模型给出的组、发表时间和非标题材料 | 无法识别 #17、#25 的无关报道，也无法判定 #24 的综述不属于原始研究证据 |
| 同源 | `prepare_sources` 以模型给的 `evidence_group` 和 DOI 合并 | DOI 覆盖不了无 DOI 的同一成果转载；错误分组会制造虚假共识；同一论文不同报道也可能被误当多项研究 |
| 补选 | 数量不足时 `RESELECT` 再从同一候选池找 3 篇 | 语义不合格时没有可靠的“停止”判断，补选会再次扩大题目 |
| 外部补充 | 用候选自拟的一条宽查询取 OpenAlex 摘要和网页正文，最多 5 篇，直接交给撰稿 | #16、#18 的补充资料与议题无关；能获取正文不等于可纳入 |
| 撰稿 | `SpecialDocument` 强制 3–5 条发现；每条只需至少一条引文；概述与发现只需出现一条站内引用 | #15、#20–#22 的补充发现引用站外资料却缺站内证据；为填满发现而外推；引文原文包含某词不代表整句结论被支持 |
| 审查 | 程序核对引文摘录是否为原文子串，再让模型审查整篇 | 无法程序判定标题与证据范围、因果归因、同一结果变量和时间线日期的语义支持 |

其中“为凑数量导致错误聚类”是依据代码门槛和失败样例作出的机制推断，需要用实际请求日志与来源快照复核；不能把相关性错误全部归因于单一提示词。

## 研究依据

1. **同一事件先消歧，再聚类。**跨文档事件共指的目标是判断不同文本是否指向同一个现实事件，而不是共享主题词。[跨文档事件共指研究](https://aclanthology.org/2023.emnlp-main.294/)和[中文事件共指数据研究](https://aclanthology.org/2024.lrec-main.523/)支持把主体、动作、对象、时间、地点及上下文作为事件身份线索。工程上应把词向量或标签相似度只用于召回，再作“同一事件”判定。
2. **研究问题先定纳入条件。**[Cochrane Handbook 第 3 章](https://www.cochrane.org/authors/handbooks-and-manuals/handbook/current/chapter-03)要求在综合前说明研究问题、纳入标准和结果的分组规则。PICO 适合干预问题；农业遥感、算法性能等议题应换成“对象/任务、数据与场景、比较对象、指标或结果、设计”字段，不能机械套用干预模板。[第 4 章](https://www.cochrane.org/authors/handbooks-and-manuals/handbook/current/chapter-04)也提醒 PICO 并不适用于所有研究类型。
3. **一项研究是一个证据单元。**[Cochrane Handbook 第 5 章](https://www.cochrane.org/authors/handbooks-and-manuals/handbook/current/chapter-05)明确要求合并同一研究的多篇报告，避免把报道数当研究数；DOI 只是其中一个线索，还需作者、机构、地点、样本、干预、日期等身份信息。事件专题则把同一次发布的转载与解读归为同一消息谱系。
4. **引用必须支持所附主张。**[ALCE 引文评估](https://aclanthology.org/2023.emnlp-main.398/)和[归因评估研究](https://aclanthology.org/2023.cl-4.2/)都将“是否由证据支持”与“是否有引用”区分开。当前的逐字摘录检查只能防止伪造摘录，不能证明引用与句子之间存在支持关系。长段落拆成可核查的原子主张有帮助，但[主张分解研究](https://aclanthology.org/2024.starsem-1.13/)也显示分解本身会引入误差，仍需保留完整句子的上下文校验。
5. **综合要保留分歧和条件。**[多文档综合实验](https://aclanthology.org/2024.tacl-1.58/)发现模型对输入顺序敏感、对来源组成不够敏感，支持在合并前显式记录每项研究的对象、结果变量、条件与局限；无合适共同结论时弃答。[非随机研究解释指南](https://www.cochrane.org/authors/handbooks-and-manuals/handbook/current/chapter-24)指出设计特征影响因果解释，前后变化不能自动写成干预效果。

这些文献提供方法原则，未直接验证本项目所用模型或农业语料上的准确率；上线阈值须由本项目样本校准。

## 建议的专题身份与纳入规则

### 事件追踪

先定义事件指纹：`主体 + 动作/决定 + 对象/成果 + 发生阶段 + 时间地点`。同一机构的另一次发布、同一技术领域的研究、以及仅提到该机构的背景报道，都不是该事件的核心材料。转载与原始公告可共同描述事件，但只算一条证据谱系；消息来自谁、效果数据由谁声称，应单独记录。

自动建立**多来源事件专题**前，应至少有两篇可读、指向同一事件的站内材料。若只有一篇，保留为单篇新闻或待追踪候选，不扩大事件范围去满足数量。独立核验不足时，仍可准确报道“某机构称”，并显式说明未获独立验证。新阶段应对应新决定、新数据或新结果；报道日期与事件发生日期分别保存。

### 研究前沿

先填写研究问题卡：`研究对象/人群、任务或干预、比较或基线、目标结果变量、场景/数据、允许的研究设计`。核心来源必须直接测量或分析所列问题；综述和仅标题来源只能作背景。自动建立**研究综合专题**前，应至少有两项独立原始研究直接回答同一问题。文献篇数和媒体转载篇数不替代研究数。若独立研究不足，保留单篇解读或候选，不把“同一方法领域”当成“同一研究问题”。

上述“至少两篇/两项”是拟议的产品门槛，需在历史样本上比较漏报和误报；现有固定“三篇核心、两组证据、三条发现”不应作为寻找无关材料的理由。近 7 天发表可用于排序和“是否值得更新”的判断，时间窗内的材料数量应与主题可回答性分开记录。

## 目标流水线与程序边界

| 阶段 | 输出和判定 | 程序必须检查的内容 |
| --- | --- | --- |
| 1. 单篇标准化 | 原始 URL、规范 DOI、来源/作者/机构、发表日、正文可用性、转载链接、内容类型 | 只有标题或访问验证页不得成为实质证据；保存可追溯文本快照 |
| 2. 候选召回 | 事件按实体与事件触发词、研究按问题卡字段召回；向量相似度只作候选 | 召回中包含相似但不同事件/研究的反例；不以链式相似关系自动并组 |
| 3. 逐篇筛选 | 对每篇给 `core / background / exclude / uncertain`、具体匹配字段、原文证据片段、排除原因 | 每个拟纳入核心来源都要有可在原文定位的片段；未判定、仅标题、未测目标结果的材料不得计入核心；未知时停在候选 |
| 4. 证据单元合并 | 研究用工作 ID；事件用原始公告/消息谱系 ID；保存“为何相同/为何独立” | DOI 等确定性标识先合并；模型只处理剩余疑难；独立性存证，不能只接受自由填写的组名 |
| 5. 可回答性判定 | 根据真实核心与独立单元决定 `ready / hold`，列出缺口 | 筛选后再计数；同一结果变量是否可比较；研究设计是否支持拟写的因果措辞 |
| 6. 外部检索 | 由问题卡生成限定查询，获取全文或原始摘要，再逐篇筛选 | 搜索摘要只作线索；核验身份、相关性、来源类型和与站内材料的同源关系；拒绝无关结果 |
| 7. 主张台账 | 每条主张对应来源片段、证据单元、支持/反对/背景关系、效果类型和限定 | 关键发现至少有一条直接站内证据；`shared` 要有两个独立证据单元支持同一主张，不能只支持相邻但不同的结果 |
| 8. 成稿与复核 | 只从已通过的主张写标题、概述、发现、比较和时间线 | 逐条验证来源确实支持整个主张；检查标题是否覆盖了未测变量；概述逐句可回溯；无法修复时弃稿 |

逐篇筛选和主张复核可以使用模型，但模型的“通过”不能代替程序校验。程序应验证 ID、来源可读性、日期、证据片段、去重、引用角色及数量；语义支持和因果边界由单独的审查步骤判定，并记录理由。审查返回信息不足时视为 `uncertain`，不自动发表。已有专题更新也应重新筛选全部核心来源，历史关联不能无条件继承为核心；人工锁定的文章要显式标注人工决策。

把文稿的发现条数放宽到 1–5，概述长度随证据量变化。不能通过添加“未解问题”或仅由外部来源支持的发现来填满模板。比较表须区分原文报告的变化、作者估计的关联、具有可识别对照的因果估计；无反事实的前后收入变化只能写“报告观察到变化”，不能写成 CSA 或 VSLAs 导致增收。

## 评估与上线顺序

1. 冻结 #15–#25 的候选输入、实际正文/摘要、模型输出及人工审核意见，形成**回放集**。当前仅有审核摘要，不能据此计算准确率。每个样例标注议题边界、逐篇角色、同源关系、可支持的主张和允许的结论强度。增加“同机构不同事件”“同技术不同结果变量”“同论文多媒体转载”“标题页/访问验证页”等困难反例，并记录可发表的正例。
2. 先在回放集上比较旧版与新版：核心纳入精确率、误并组率、漏合组率、关键主张支持率、标题覆盖错误、因果越界率、应弃答时的误发布率，以及真正可发表专题的召回率。把人工分歧样例单列，不用单一模型审批当真值。#15–#25 所指出的错误不得在新版重现；同时验证正例没有全部被错误弃答。
3. 将新流程置于仅记录结果的影子运行，比较每日候选、耗时和模型调用成本；人工抽样核对连续多天的通过与拒绝案例。达到事先确定的质量门槛后，再让新版自动发布。已有错误专题需要按新边界逐篇重审，不能通过再次运行旧成稿器自动洗白。

建议在代码中把 `special_service.py` 拆为候选召回、逐篇筛选、证据谱系、主张台账与发布编排；`special_research.py` 只负责检索和抓取，纳入决策交给同一逐篇筛选器。版本快照保存每篇的纳入/排除理由、原文片段、证据单元和审查版本，让管理后台能直接解释“为何这篇在专题里”。重构过程中保留现有版本签名校验和人工锁定机制。
